## 5. Content and accessibility

- Use plain, specific labels and action-oriented button text.
- Support keyboard navigation, visible focus, semantic structure, and sufficient contrast.
- Provide text alternatives for meaningful visual/media content.
- Test key flows on small screens and with assistive technology.

## 6. Frontend handoff checklist

- Route/page purpose and component hierarchy are defined.
- Desktop, mobile, loading, empty, success, and error states are designed.
- API data needed by each screen is named; do not rely on unspecified data.
- Form fields specify validation, required state, helper text, submission behavior, and error copy.
- Permissions, unavailable actions, and destructive actions have a clear user experience.
- Tokens, reusable components, assets, and responsive behavior are documented.
